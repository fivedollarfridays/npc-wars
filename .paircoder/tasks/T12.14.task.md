# Objective

End-to-end integration tests validating the full Watcher pipeline: spawn, pattern recording, counter-action selection, sync calculation, memory persistence, and spectacle events working together in a simulated match with mock human input. Depends on T12.1-T12.13.

# Implementation Plan

1. **Create `tests/test_integration_watcher.py`** with integration tests:
   - **Spawn test**: Run a match with 1 mock human bot (simulated overrides) and 5 regular bots. Verify The Watcher spawns after the human survives 5 rounds with >50% HP.
   - **Pattern recording test**: After a match with mock human, verify the pattern table contains entries for the human player with correct contexts (after_damage, at_range_1, etc.)
   - **Counter-action test**: Set up a pattern table with known data, verify `select_counter_action` returns a valid counter for the predicted human action
   - **Sync calculation test**: Simulate 10 rounds of predictions, verify sync percentage matches expected rolling accuracy
   - **Memory persistence test**: Run a match, save memory to a temp file, load from the temp file, verify pattern data is intact (roundtrip)
   - **Rubber-banding test**: Verify Watcher accuracy drops when human is losing and increases when human is dominating
   - **Full pipeline test**: Run a complete multi-round match simulation exercising spawn -> observe -> predict -> counter -> sync -> spectacle events

2. **Create shared fixtures in `tests/conftest.py`** (or a local conftest):
   - `mock_human_bot` — a bot that simulates human overrides with predictable patterns
   - `populated_pattern_table` — a `PatternTable` pre-loaded with known frequency data
   - `tmp_memory_path` — temporary file path for persistence tests

3. **Fix any remaining failures** across the full Watcher test suite

# Acceptance Criteria

- [ ] All tests pass
- [ ] Watcher spawns in mock human match
- [ ] Pattern table populated after match
- [ ] Memory persists after save/load
