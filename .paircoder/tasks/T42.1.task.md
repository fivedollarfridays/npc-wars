# Objective

Add API key authentication and bot source persistence to the server. Players get an API key on first upload, which they use for all subsequent requests.

# Context

- `server/db.py` already has players table (id, name, created_at) and sessions table
- `server/middleware/session.py` has session cookie middleware
- `server/routes/submit.py` has POST /api/submit-bot that validates but doesn't persist

# Implementation Plan

1. Add to `server/db.py`:
   - `api_keys` table: key (TEXT PRIMARY KEY), player_id (INTEGER), created_at
   - `bots` table: id (INTEGER PRIMARY KEY), player_id, name, emoji, source (TEXT), created_at, updated_at
   - `create_api_key(player_id) -> str` — generate UUID API key
   - `get_player_by_api_key(key) -> dict | None`
   - `store_bot(player_id, name, emoji, source) -> int` — save bot, return bot_id
   - `get_player_bots(player_id) -> list[dict]`
   - `get_bot(bot_id) -> dict | None`

2. Add API key middleware or dependency:
   - Check `X-API-Key` header or `api_key` query param
   - If no key: auto-generate player + key on first request, return in response
   - If key: validate, attach player_id to request state

3. Update POST /api/submit-bot:
   - Require valid API key (or auto-generate)
   - After validation, store bot source in `bots` table
   - Return bot_id + API key (if newly generated)

4. Add GET /api/bots — list player's uploaded bots
5. Add GET /api/bots/{bot_id} — get specific bot details

6. Tests in `tests/test_player_auth.py`

# Acceptance Criteria

- [ ] API key generated on first request
- [ ] API key validates on subsequent requests
- [ ] Bot source stored in database with player ownership
- [ ] GET /api/bots lists player's bots
- [ ] Invalid API key returns 401
