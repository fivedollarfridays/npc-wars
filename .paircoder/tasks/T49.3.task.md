# Objective

Fix rate limiter bypass (keyed on spoofable session cookie) and unhandled ValueError in stats route.

# Implementation Plan

1. Fix `server/middleware/rate_limit.py`:
   - Key rate limiting on player ID from `get_current_player()` instead of session token
   - Fallback to IP address (`request.client.host`) if no player auth
   - Add max size cap on `_submissions` dict (e.g., 10000 entries)
   - Add cleanup on every check (not just at 1000+ threshold)

2. Fix `server/routes/stats.py` (line 29):
   - Validate `sort_by` parameter against allowed values at route level
   - Return 400 with safe message on invalid sort_by
   - Don't rely on data layer ValueError (defense in depth)

3. Tests in `tests/test_s49_rate_limit.py`:
   - Rate limit works with player ID (not cookie)
   - Rate limit works with IP fallback when no auth
   - Different cookies same player = same rate limit bucket
   - Max dict size enforced
   - Stats route returns 400 on invalid sort_by (not 500)
   - Stats route returns valid data on valid sort_by values

# Acceptance Criteria

- [ ] Rate limiter keyed on player ID or IP, not session cookie
- [ ] _submissions dict has max size cap
- [ ] Stats route validates sort_by, returns 400 on invalid
- [ ] Tests pass, ruff clean
