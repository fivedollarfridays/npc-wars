# Objective

Throttle The Watcher's prediction accuracy to keep matches competitive. When a human is losing, The Watcher intentionally misses more predictions (60% cap). When the human is dominating, The Watcher plays near-perfectly (95% cap). The player never knows the cap value -- they just feel the difficulty adjusting. Depends on T12.4, T12.5. Reference: docs/RESEARCH-spectacle-and-human-play.md Section 7 (Rubber-Banding).

# Implementation Plan

1. **Create `tests/test_rubber_banding.py`** with tests for:
   - Losing human (low HP, no kills) -> accuracy cap is 60%
   - Even match (trading blows, moderate HP) -> accuracy cap is 75%
   - Winning human (got kills, high HP) -> accuracy cap is 90%
   - Dominating human (multiple kills, near-full HP) -> accuracy cap is 95%
   - Cap applied probabilistically: when random() > cap, Watcher uses random action instead of counter
   - Performance measured by: HP ratio (current/max), kill count, rounds survived

2. **Add to `engine/watcher_brain.py`**:
   - `HumanPerformance` dataclass with fields: `hp_ratio: float`, `kills: int`, `rounds_survived: int`
   - `get_accuracy_cap(performance: HumanPerformance) -> float` — returns accuracy cap (0.0-1.0):
     - `hp_ratio < 0.3 and kills == 0` -> 0.60
     - `hp_ratio < 0.5 or kills <= 1` -> 0.75
     - `hp_ratio >= 0.5 and kills >= 2` -> 0.90
     - `hp_ratio >= 0.7 and kills >= 3` -> 0.95
   - `apply_accuracy_cap(counter_action: tuple, cap: float, all_actions: list, rng) -> tuple` — if `rng.random() > cap`, return a random action from `all_actions` instead of `counter_action`
   - Wire cap into `select_counter_action` flow

3. **Run tests and verify** all pass
