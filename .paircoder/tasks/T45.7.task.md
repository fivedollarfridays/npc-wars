# Objective

1. When a bot hits the 3-failure safety net, generate a visible "malfunction" event instead of silent death.
2. Fix trapper.py and viper.py to check unlocked_actions before using advanced features.

# Implementation Plan

## Malfunction events

In `engine/rounds.py` where `bot.hp = 0` on consecutive failures (line ~94):
- Generate an event: `{"type": "malfunction", "emoji": bot.emoji, "reason": "Bot crashed 3 times", "round": round_num}`
- Add to round events so viewer can display it

In viewer:
- `viewer/js/events.js`: add malfunction event rendering (red "⚠ MALFUNCTION" text on tile)
- `viewer/js/events.js`: add kill feed entry for malfunction

## Fix broken bots

In `bots/example_trapper.py`:
- Check `state["me"].get("unlocked_actions", [])` before returning trap action
- Fall back to attack/move if trap not unlocked

In `bots/viper.py`:
- Same: check unlocked_actions before using trap
- Use `.get("max_hp", 145)` instead of direct key access (already partially fixed)

# Acceptance Criteria

- [ ] Malfunction event generated when bot hits 3-failure limit
- [ ] Viewer shows malfunction in kill feed
- [ ] trapper.py works without trap unlocked (falls back to basic actions)
- [ ] viper.py works without trap unlocked
- [ ] Tests pass
