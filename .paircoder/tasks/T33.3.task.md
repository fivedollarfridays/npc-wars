# Objective

Wire the `react` callback into the match loop. Called after combat resolution each round for bots at level 12+ that have a `react()` function. Provides nearby action/event info so bots can adapt.

# Background

The `react(state, events)` callback enables reactive play — bots see what happened around them and can update internal state (tracking, targeting, momentum strategy). It does NOT return an action; it's read-only observation. This is the key gameplay unlock at level 12.

# Design Decisions

- **Scope:** Called for all alive bots with the callback, every round
- **Events parameter:** List of dicts describing what happened this round within the bot's visibility radius (3 tiles). Format: `[{"type": "attack", "attacker": "🤖", "target": "🎯", "damage": 25}, ...]`
- **Timing:** After combat resolution, after scoring, before next round's decide()
- **Constraints:** Read-only. No return value used. Timeout 0.1s. Exceptions caught.

# Implementation Plan

1. Create `_build_nearby_events(bot, round_events, all_bots) -> list[dict]` — filters round events to those within 3 tiles of the bot
2. Add `_execute_react_callbacks(bots, round_events)` function
   - For each alive bot with `callbacks.react is not None`:
     - Build state dict
     - Build nearby events list
     - Call `execute_callback(bot.callbacks.react, state, nearby_events)`
3. Wire into `run_match()` after `_apply_momentum_phase()` but before next round
4. Wire into `run_match_async()` similarly
5. Add test bot fixture with `react()` that tracks kill events

# Acceptance Criteria

- [ ] react() called every round for alive bots with the callback
- [ ] Events filtered to 3-tile radius around the bot
- [ ] react() receives state dict + events list
- [ ] Bot exceptions in react() are caught, match continues
- [ ] Bots without react callback are unaffected
- [ ] Tests pass, ruff clean, < 400 lines
