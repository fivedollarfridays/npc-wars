# Objective

Add a proper `/viewer` route and fix match path resolution so the editor can link to the viewer with a match ID.

# Implementation Plan

1. Add viewer route in `server/routes/pages.py`:
   - `GET /viewer` → serve `viewer/index.html` (or `viewer/match.html`)
   - Query params pass through (`?match=...`)

2. Fix match path validation in `viewer/js/app.js`:
   - Current regex: `/^results\/match_\d{3,}\.json$/` — rejects API paths
   - Add API loading path: if `?match=` param is not a file path, treat as match ID
   - Fetch from `/api/match/{match_id}` when param looks like an ID (numeric or UUID)
   - Keep existing file path loading for backwards compat

3. Verify `GET /api/match/{match_id}` in `server/routes/match.py`:
   - Works for numeric IDs (match_NNN)
   - Works for UUID job IDs (from lobby submit flow)
   - Returns full match JSON

4. Tests in `tests/test_s48_viewer.py`:
   - `GET /viewer` returns 200
   - Viewer HTML loads with proper JS includes
   - `/api/match/{id}` returns JSON for valid match
   - Viewer JS accepts both file paths and match IDs

# Acceptance Criteria

- [ ] `GET /viewer` serves the match viewer page
- [ ] Viewer loads matches from `/api/match/{id}` (not just file paths)
- [ ] Both UUID and numeric match ID formats work
- [ ] Backwards compat: file path loading still works
- [ ] Tests pass, ruff clean
