# Objective

Ensure the lobby status API returns all data the browser needs and that the lobby timer actually fires in the background.

# Implementation Plan

1. Update `server/routes/lobby.py` — enhance `/api/lobby/status` response:
   - Current: `{players: int, max: int, time_remaining: float, triggered: bool}`
   - New: add `player_list: [{emoji: str, name: str}]`, `match_id: str|null`, `status: "waiting"|"filling"|"running"|"complete"`
   - When match completes, `match_id` field populated so browser can redirect

2. Update `server/lobby.py` — expose richer state:
   - Track `match_id` when match triggers (store from queue response)
   - Return player emoji + name in status (not just count)
   - Add `tick()` method that calls `check_timer()` and returns current state

3. Wire background timer — simplest approach:
   - Call `lobby.check_timer()` inside the `GET /api/lobby/status` handler (fires on poll)
   - This avoids background task complexity — timer fires every time browser polls

4. Tests in `tests/test_s48_lobby.py`:
   - Status response includes `player_list` array with emoji/name dicts
   - Status response includes `status` field with valid values
   - Timer triggers match when expired
   - `match_id` populated after trigger

# Acceptance Criteria

- [ ] `/api/lobby/status` returns `player_list` with emoji + name per player
- [ ] Status includes `match_id` when match triggered
- [ ] Lobby auto-triggers after 30s timeout (via poll-driven timer check)
- [ ] Tests pass, ruff clean
