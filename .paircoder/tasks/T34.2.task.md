# Objective

Wire the `on_kill` callback into the match loop so it fires when a bot eliminates another. Currently defined in CallbackSet but never called during gameplay.

# Background

The callback registry (S33) supports `on_kill` discovery, and `Bot.callbacks.on_kill` is populated, but no code in the game loop calls it. Level 5+ bots should receive this callback after a kill is attributed.

# Implementation Plan

1. Add `run_on_kill_callbacks(killer_bot, victim_bot, all_bots, round_num, grid_size, storm_border)` to `engine/callback_runner.py`
   - Build state dict for the killer
   - Call `execute_callback(killer.callbacks.on_kill, state, victim.emoji)`

2. Wire into `engine/game.py` `_resolve_combat_phases()`:
   - After `attribute_kills()` (which sets kill attribution), iterate round eliminations
   - For each elimination with a valid killer, call `run_on_kill_callbacks()`
   - Skip storm/plague/tiebreaker kills (no player killer)

3. Wire into `engine/game_async.py` similarly

4. Tests in `tests/test_on_kill_callback.py`:
   - on_kill fires when bot eliminates another
   - on_kill receives state + victim emoji
   - on_kill NOT called for storm/plague kills
   - Exception in on_kill doesn't crash match
   - Bot without on_kill callback unaffected

# Acceptance Criteria

- [ ] on_kill() fires after a bot eliminates another in combat
- [ ] on_kill() receives state dict + victim emoji string
- [ ] Storm/plague/tiebreaker kills don't trigger on_kill
- [ ] Exceptions caught, match continues
- [ ] Tests pass, ruff clean
