# Objective

Embed spectacle data into the match JSON output so that renderers (HTML viewer and video renderer) can consume drama scores, tiers, triggers, and effects per round. Wire `SpectacleEngine` into the round execution pipeline.

# Implementation Plan

1. **Add tests to `tests/test_spectacle.py`** for match JSON integration:
   - Round data dictionary contains a `"spectacle"` key
   - Spectacle object has `drama_score` (int), `tier` (str), `triggers` (list), `effects` (list)
   - Spectacle data varies between rounds with different events

2. **Add tests to `tests/test_game.py`** for end-to-end:
   - Run a match and verify every round in the output JSON has a `"spectacle"` object
   - Verify existing match JSON fields (positions, events, eliminations) are unchanged
   - Verify spectacle data is present even for calm rounds (drama_score=0, tier="calm")

3. **Wire `SpectacleEngine` into `engine/game.py`**:
   - Import `SpectacleEngine` in `game.py`
   - After `_execute_round` resolves events, call `spectacle_engine.score_round(events, bots)`
   - Add the returned `SpectacleData` as a `"spectacle"` dict to `build_round_record` output
   - Schema: `{"drama_score": int, "tier": str, "triggers": list[str], "effects": list[str]}`

4. **Ensure backward compatibility**:
   - Existing round fields (`round`, `storm_border`, `positions`, `events`) remain unchanged
   - Spectacle is additive -- new key only

# Acceptance Criteria

- [ ] Each round in match JSON has a `"spectacle"` object
- [ ] Spectacle contains `drama_score` (int), `tier` (str), `triggers` (list), `effects` (list)
- [ ] Existing match JSON fields are unchanged (no regressions)
