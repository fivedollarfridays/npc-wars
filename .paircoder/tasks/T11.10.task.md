# Objective

Record human copilot overrides as events in the match JSON for replay analysis. When a human overrides their bot's decision, emit a `"human_override"` event containing the player emoji, the original bot action, and the human's override action. No event is generated when the human does not override.

# Implementation Plan

1. **Create `tests/test_human_events.py`** with tests for:
   - Human override generates a `"human_override"` event in the round's events list
   - Event contains `player` (emoji str), `original` (bot's action as string), `override` (human's action as string)
   - No event generated when human adapter returns `None` (bot decision used)
   - No event generated when human's action matches the bot's action (no actual override)
   - Multiple humans overriding in the same round each generate their own event

2. **Add event emission to the copilot override logic** (in `engine/rounds.py` or equivalent):
   - After comparing bot decision vs human input:
     - If human provided an action AND it differs from the bot's action:
       - Append `{"type": "human_override", "player": bot_emoji, "original": str(bot_action), "override": str(human_action)}` to round events
     - If human provided `None` or same action as bot: no event emitted
   - Action strings should be human-readable, e.g., `"move east"`, `"attack north"`, `"rest"`, `"defend"`

3. **Verify schema in match JSON output**:
   - The `"human_override"` event follows the same schema as other events in the events list
   - Events are ordered chronologically within the round (overrides happen before resolution)

# Acceptance Criteria

- [ ] Human overrides generate `"human_override"` events in round data
- [ ] Event contains original bot decision and human override action as strings
- [ ] No event generated when human does not override (timeout or same action)
