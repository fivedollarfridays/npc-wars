# Objective

Convert the match loop to support async execution with a 2-second human input window per round. When humans are present, the engine opens an input window after bot decisions are collected. When no humans are present, the async loop behaves identically to the existing sync loop.

# Implementation Plan

1. **Create `tests/test_async_match.py`** with tests for:
   - Async match with 0 humans produces identical results to sync match (same seed, same output)
   - Round completes within timeout when human responds quickly
   - Bot fallback occurs when human times out (2-second window expires)
   - Multiple humans can input simultaneously in the same round
   - Match runs to completion with a mix of responding and timing-out humans

2. **Add `async run_match_async()` to `engine/game.py`**:
   - Mirror the existing `run_match` logic but with `async`/`await`
   - Round flow:
     1. Bot `decide()` runs for all bots (existing, synchronous via multiprocessing sandbox)
     2. If any bot has a `human_adapter`, open a 2-second input window
     3. Use `asyncio.gather` with `asyncio.wait_for` to collect all human inputs concurrently
     4. Apply overrides (from T11.3 copilot logic)
     5. Resolve round (existing pipeline: defense -> movement -> attacks -> storm)
   - Return the same match data structure as `run_match`

3. **Bridge sync and async**:
   - Modify `run_match` to detect if any bots have human adapters
   - If humans present: call `asyncio.run(run_match_async(...))` or use an event loop
   - If no humans: run existing sync path (zero overhead for pure bot matches)

4. **Timeout handling**:
   - Each human adapter's `get_action` is wrapped in `asyncio.wait_for(timeout=2.0)`
   - On `asyncio.TimeoutError`, the bot's original decision is used
   - Log timeout events for AFK detection (T11.9)

# Acceptance Criteria

- [ ] Async match loop runs correctly with 0 humans (identical output to sync match)
- [ ] 2-second input window per round when humans are present
- [ ] Multiple humans can input simultaneously via `asyncio.gather`
- [ ] Timeout results in bot fallback (bot's `decide()` output used)
