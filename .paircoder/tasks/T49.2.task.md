# Objective

Fix stored XSS vulnerabilities in tournaments.html, leaderboard.html, and profile.html where user-controlled data is rendered via innerHTML without sanitization.

# Implementation Plan

1. Create a shared `sanitize()` JS function (already exists in `viewer/js/app.js`):
   - Add inline sanitize helper to each affected page (or a shared `server/static/js/sanitize.js`)
   - Function: create temp div, set textContent, return innerHTML

2. Fix `server/static/tournaments.html` (lines 37-38):
   - Sanitize `t.name` before innerHTML: `sanitize(t.name)`
   - Sanitize `t.winner` before innerHTML: `sanitize(t.winner)`
   - Sanitize `t.status` for safety

3. Fix `server/static/leaderboard.html` (line 122):
   - Sanitize `p.emoji` before innerHTML insertion
   - Sanitize `p.name` if rendered anywhere

4. Fix `server/static/profile.html` (line 189):
   - Sanitize `m.winner` before innerHTML insertion
   - Check all other innerHTML usage for user data

5. Tests in `tests/test_s49_xss.py`:
   - Each HTML file contains `sanitize` function or import
   - Known XSS payloads in bot names don't appear raw in rendered HTML
   - Test that `<script>` in emoji field gets escaped
   - All existing HTML file tests still pass
