# Objective

Render terrain tiles on the viewer canvas. Walls, water, high ground, cover, and crystals should be visually distinct with fills and colors.

# Current State

- Canvas renders a dark background with faint grid lines (0.04 opacity)
- Storm overlay renders purple tinted areas
- No terrain data is used — the `terrain_tiles` field in match JSON is ignored
- Match JSON has `terrain_tiles` (2D array of tile type strings) and `map` (map name)

# Implementation Plan

In `viewer/match.html`, modify the `renderCanvas` function:

1. After clearing canvas and before drawing grid, render terrain tiles:
   - Read `matchData.terrain_tiles` (2D array: tiles[y][x] = "open"/"wall"/"water"/"high_ground"/"cover"/"crystal")
   - For each tile, fill with terrain-specific color:
     - `open` → transparent (default dark background)
     - `wall` → dark gray solid fill (#2a2a3a) with slightly lighter border
     - `water` → dark blue fill (#0a1a3a) with subtle wave pattern (horizontal lines)
     - `high_ground` → dark yellow/gold fill (#2a2a1a) with upward triangle indicator
     - `cover` → dark green fill (#1a2a1a) with small shield icon
     - `crystal` → dark magenta fill (#2a1a2a) with star/sparkle indicator
   - Draw terrain BEFORE bots so bots render on top
   - Use dim/muted colors so terrain is visible but doesn't compete with action

2. Handle missing terrain data (backward compat with old match JSONs):
   - If `terrain_tiles` not present, skip terrain rendering (all open)

3. Add map name display in match info header

# Acceptance Criteria

- [ ] Walls render as solid dark blocks
- [ ] Water renders with blue tint
- [ ] High ground renders with gold tint
- [ ] Cover renders with green tint
- [ ] Crystals render with magenta sparkle
- [ ] Old match JSONs without terrain_tiles still work
- [ ] Terrain doesn't overwhelm bot/effect visibility
