# Objective

Wire the lobby system into HTTP endpoints and connect the full pipeline: bot upload → lobby join → queue → worker → match → replay.

# Context

- `server/lobby.py` has Lobby class with join(), status(), is_ready()
- `server/queue.py` has enqueue_match(), dequeue_match()
- `server/worker.py` has Worker that polls queue and runs matches
- The pipeline exists in pieces but isn't connected end-to-end

# Implementation Plan

1. Add lobby HTTP endpoints to `server/routes/`:
   - POST /api/lobby/join — add player's bot to lobby (requires bot_id or inline source)
   - GET /api/lobby/status — current lobby state (players, time remaining, ready status)
   - GET /api/lobby/history — list of recent match IDs for this player

2. Wire the pipeline:
   - POST /api/submit-bot validates + stores bot → returns bot_id
   - POST /api/lobby/join with bot_id → adds to lobby
   - When lobby fills (4+ bots or 30s timeout):
     - Auto-fill with AI bots if < 4 humans
     - Enqueue match job to queue
   - Worker dequeues and runs match via run_match()
   - Match result stored in results/ directory
   - Player can GET /api/match/{match_id} to retrieve replay

3. Add background task to check lobby timer:
   - FastAPI lifespan event starts a background task
   - Checks lobby.is_ready() periodically (every 1s)
   - When ready, triggers match creation + enqueue

4. Add match notification:
   - After match completes, store match_id in player's match history
   - GET /api/lobby/history returns recent match IDs

5. Tests in `tests/test_lobby_http.py`

# Acceptance Criteria

- [ ] POST /api/lobby/join adds bot to lobby
- [ ] Lobby auto-triggers match when 4+ bots ready
- [ ] AI bots fill empty slots
- [ ] Match result accessible via GET /api/match/{id}
- [ ] Player can see their match history
