# Objective

Create a mutation engine that reads bot source code via AST, identifies numeric thresholds in comparison expressions, and produces mutant variants with adjusted values.

> **AW2 context:** This is the v1 (offline) mutation engine — programmatic threshold tweaking with no LLM dependency. AW2 Sprint 7 (ranked + LLM integration) extends this with LLM-powered rewrites guided by engineer mode critique scores. The two mutation strategies coexist: AST mutation runs free/offline, LLM mutation activates when an API key is configured.

# Implementation Plan

1. Create `agentgrounds/wars/mutator.py`:
   - `find_thresholds(source: str) -> list[Threshold]`: parse AST, find numeric literals in `Compare` nodes (e.g., `if me.energy < 30` → threshold at line N, value 30)
   - `Threshold` dataclass: `line`, `col`, `original_value`, `context` (the comparison expression as string)
   - `mutate_threshold(source: str, threshold: Threshold, rng: Random, range_pct: float = 0.2) -> str`: replace the numeric literal with a value ±range_pct of original
   - `mutate_bot(source: str, rng: Random, mutation_rate: float = 0.3) -> str`: randomly select ~30% of thresholds and mutate each
   - `create_mutant(source: str, name: str, emoji: str, rng: Random) -> str`: produce a complete mutant bot file with new BOT_NAME and BOT_EMOJI
   - Validate mutant passes `scan_bot_source()` — import from `agentgrounds.wars.engine.bot_scanner`
2. Only mutate integer and float literals in `ast.Compare` nodes
3. Clamp mutations to reasonable ranges (no negative HP thresholds, etc.)
4. Validate mutant passes `scan_bot_source()` before returning
5. If mutation produces invalid code, retry with different random values (max 3 attempts)

# Acceptance Criteria

- [ ] `find_thresholds` identifies numeric literals in comparisons
- [ ] `mutate_threshold` adjusts value by ±20% (configurable)
- [ ] `mutate_bot` applies mutations to ~30% of thresholds
- [ ] `create_mutant` produces a valid bot file with new identity
- [ ] Mutants pass `scan_bot_source()` validation
- [ ] Invalid mutations are retried (max 3 attempts)
- [ ] Tests cover: threshold finding, mutation ranges, identity assignment, validation
