# Objective

Update the starter bot to demonstrate memory-aware strategy and write an E2E integration test proving the full memory lifecycle works.

# Implementation Plan

1. Add a memory-aware section to `bots/starter.py`:
   ```python
   # ═══════════════════════════════════════════════════
   # MEMORY: Learn from past matches
   # state["memory"] persists between matches.
   # TODO: Track what works and adapt!
   #   - Count wins/losses and adjust aggression
   #   - Remember which enemies are dangerous
   #   - Store optimal energy thresholds
   # ═══════════════════════════════════════════════════
   memory = state.get("memory", {})
   matches = memory.get("matches", 0)
   wins = memory.get("wins", 0)

   # After a few matches, adapt based on win rate
   if matches >= 3:
       win_rate = wins / matches
       if win_rate < 0.2:
           ENERGY_THRESHOLD = 20  # losing → be more aggressive
       elif win_rate > 0.5:
           ENERGY_THRESHOLD = 40  # winning → stay conservative
   ```
2. At the end of the decide function, update memory counters (memory is a live reference):
   ```python
   memory["matches"] = matches  # will be incremented by engine
   # Note: win/loss tracking requires post-match hook, not in decide()
   ```
3. Actually — tracking wins requires the engine to update memory after the match. Add a convention: the engine sets `bot.memory["_last_match_won"] = True/False` during `_finalize_match()`.
4. Copy updated starter to `npcwars/builtin_bots/starter.py`
5. Update PROMPT.md to mention the memory feature
6. Integration test in `tests/test_s21_integration.py`:
   - Run match 1 with memory_dir → verify memory files created
   - Run match 2 with same memory_dir → verify memory loaded and updated
   - Verify `state["memory"]` is accessible in decide()
   - Verify `--fresh` clears memory between runs
   - Verify `--no-memory` skips memory entirely
   - Verify starter bot uses memory without crashing
