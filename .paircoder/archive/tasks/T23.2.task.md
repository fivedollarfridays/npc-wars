# Objective

Build `agentgrounds wars sim` — a batch match runner that executes N matches and writes per-match results + aggregate stats. This is both a player-facing tool and the internal balance testing harness used throughout all future sprints.

# Context

Every future sprint requires running hundreds to thousands of matches to validate balance. The sim runner powers Sprint 2 tile validation (1000 matches on The Pit), Sprint 3 class balance matrix (500 matches per matchup), and ongoing regression testing. The same `agentgrounds wars sim` command is the engine behind `agentgrounds wars tournament --local`.

# Implementation Plan

1. **Create `agentgrounds/wars/cli/cmd_sim.py`**
   - Register `sim` subcommand in wars `__main__.py`
   - Arguments: `--map`, `--matches N` (default 10), `--output DIR`, `--seed`, `--bots-dir`, `--parallel`, `--quiet`

2. **Match execution loop**
   - Load bots from `--bots-dir`
   - For match 1..N: call `run_match(bot_configs, match_id=i, seed=base_seed+i)`
   - Write each result to `{output}/match_{i:04d}.json`
   - Print progress counter (e.g., `10/1000 matches complete`)

3. **Aggregate stats output**
   - After all matches, write `{output}/sim_summary.json` with:
     - `total_matches`, `avg_match_length`, `median_match_length`, `min/max_match_length`
     - `winner_distribution` (emoji → win count)
     - `placement_distribution` (rank → count per bot)
     - `avg_agents_alive_by_round` (list indexed by round)
   - Print summary table to stdout

4. **Parallel mode** — `multiprocessing.Pool` when `--parallel` set, pool size = `min(cpu_count(), 8)`, seed isolation per worker

5. **Tests** in `tests/test_sim_runner.py`
   - 5-match run: verify output files created, summary JSON valid
   - `--seed` reproducibility: same seed + bots = same winner distribution
   - `--parallel`: exits 0, same file count as sequential

# Acceptance Criteria

- [ ] `agentgrounds wars sim --matches 10 --output /tmp/sim_test` runs and exits 0
