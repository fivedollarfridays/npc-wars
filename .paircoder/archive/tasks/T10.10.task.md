# Objective

End-to-end validation of the spectacle pipeline. Run a full match, verify spectacle metadata is present in every round of the output JSON, verify tier assignments are reasonable for the events that occurred, and verify video render includes audio when spectacle data is present.

# Implementation Plan

1. **Create `tests/test_integration_spectacle.py`** with:
   - **Test: spectacle metadata in all rounds** -- run a full match with 5+ bots, load output JSON, assert every round object has a `"spectacle"` key with `drama_score`, `tier`, `triggers`, and `effects` fields
   - **Test: tier assignments are reasonable** -- for rounds with zero events, tier should be `"calm"`; for rounds with kills, tier should be at least `"heating"`; verify no tier is outside the valid set `{"calm", "heating", "intense", "hype", "chaos"}`
   - **Test: drama score consistency** -- verify drama_score is a non-negative integer for all rounds; verify rounds with more events have equal or higher drama scores than empty rounds
   - **Test: trigger-effect consistency** -- when triggers list contains `"kill_streak"`, effects list should contain `"fire_border"`; verify the mapping is consistent with T10.2 definitions
   - **Test: video render with audio** -- render a short match to video, use ffprobe (or mock) to verify the output MP4 has an audio stream when spectacle data is present

2. **Fix any failures** discovered during integration:
   - If spectacle metadata is missing from some rounds, trace through `game.py` wiring
   - If tier assignments are wrong, check `SpectacleEngine.classify_tier` boundary values
   - If audio stream is missing, check `audio/renderer.py` muxing step

3. **Run full test suite** to verify no regressions from Sprint 3 work

# Acceptance Criteria

- [ ] All integration tests pass
- [ ] Match JSON contains spectacle data in every round
- [ ] Video renders with audio stream when spectacle data is present
