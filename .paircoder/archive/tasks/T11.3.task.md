# Objective

Integrate human copilot override into the round resolution pipeline. After each bot's `decide()` runs, check for a human override from the attached `HumanInputAdapter`. If the human provides a valid action, it replaces the bot's decision for that round. If not, the bot's original action executes.

# Implementation Plan

1. **Create `tests/test_copilot.py`** with tests for:
   - Human override replaces bot's `decide()` output for the round
   - No human override (adapter returns `None`) uses bot's original decision
   - Human sees the same `state` dict that their bot receives
   - Human action is validated identically to bot actions (invalid actions rejected, bot fallback used)
   - Human override for a non-existent action (e.g., `"dash"` when not unlocked) falls back to bot

2. **Modify `engine/rounds.py`** (resolve_decisions or equivalent):
   - After collecting bot decisions via `decide()`, check if the bot has an attached `HumanInputAdapter`
   - If adapter exists, call `adapter.get_action(state, timeout_s=2.0)`
   - If adapter returns a valid action tuple, replace the bot's decision
   - If adapter returns `None` or an invalid action, keep the bot's original decision
   - Pass the human override through the same `validate_action` checks that bot actions go through

3. **Attach adapters to bots**:
   - Add optional `human_adapter: HumanInputAdapter | None` field to the bot/player data structure
   - The match runner sets this field when a human is connected to a bot
   - Adapter is `None` for pure bot participants

4. **State exposure**:
   - Human receives the exact same `state` dict as their bot -- no additional information
   - State is passed to `adapter.get_action(state, ...)` so the viewer can render it

# Acceptance Criteria

- [ ] Human action replaces bot's `decide()` output for that round
- [ ] If no human input (timeout), bot's original action is used
- [ ] Human actions validated identically to bot actions (same `validate_action` path)
- [ ] Human sees the same state dict as their bot
