# Objective

Add health check and monitoring endpoints so the load balancer and operators can verify service health and observe key metrics.

# Implementation Plan

1. Create `server/routes/health.py` with three endpoints
2. Implement `GET /health` returning extended component checks: Redis connectivity, SQLite accessibility, and disk space availability
3. Implement `GET /health/ready` as a lightweight probe for load balancer readiness checks (returns 200 when all components healthy, 503 otherwise)
4. Implement `GET /metrics` returning match count, queue depth, and active session count as structured JSON
5. Each component check should have independent try/catch so one failure does not mask others
6. Register all routes in the FastAPI app
7. Write tests covering healthy responses, degraded component scenarios, and metrics output

# Acceptance Criteria

- [x] `GET /health` returns component-level checks for Redis, SQLite, and disk space
- [x] `GET /health/ready` returns 200 when healthy, 503 when degraded
- [x] `GET /metrics` returns JSON with match count, queue depth, and active sessions
- [x] All responses are structured JSON
- [x] Tests pass for healthy state, degraded state, and metrics output
