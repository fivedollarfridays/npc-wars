# Objective

Add Redis-backed rate limiting and cookie-based session management to prevent submission abuse and track player sessions.

# Implementation Plan

1. Create `server/middleware/rate_limit.py` with a FastAPI middleware that enforces rate limits
2. Implement Redis-backed sliding window rate limiting: 1 submission per 30 seconds per session
3. Create `server/middleware/session.py` for cookie-based session token management
4. Issue session tokens via `Set-Cookie` on first request; validate on subsequent requests
5. Return `429 Too Many Requests` with `Retry-After` header when rate limit is exceeded
6. Include rate limit headers in all responses (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`)
7. Write tests covering rate limit enforcement, session creation, 429 responses, and header presence

# Acceptance Criteria

- [ ] Redis-backed rate limiting enforces 1 submission per 30 seconds per session
- [ ] Session tokens are issued via cookies
- [ ] Rate limit headers (`X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`) are present in responses
- [ ] 429 responses include a `Retry-After` header when rate limit is exceeded
- [ ] Tests pass for rate limiting, session management, and response headers
