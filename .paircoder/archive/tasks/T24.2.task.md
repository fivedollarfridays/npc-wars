# Objective

Add sub-frame rendering capability to `TerminalRenderer`. Instead of one frame per round, support splitting a round into phases: **action phase** (showing combat indicators) and **resolution phase** (showing results).

# Context

Currently `render_frame()` renders one static frame per round. To show attack/defend animations, we need to render 2 sub-frames per round:
1. **Action sub-frame** (~300ms): Shows directional attack indicators (⚔️) between attacker and target cells, shield indicators (🛡️) on defending bots
2. **Resolution sub-frame** (~700ms): Normal frame showing HP changes and kill feed

# Implementation Plan

1. **Add `WEAPON_FX` dict** to renderer for extensibility:
   ```python
   WEAPON_FX = {
       "melee": "⚔️",
       "ranged": "🏹",
       "default": "⚔️",
   }
   DEFEND_FX = "🛡️"
   ```

2. **Add `render_action_frame()` method** to `TerminalRenderer`:
   - Takes `round_data` (same as `render_frame`)
   - Builds position map like normal
   - Overlays combat indicators from `round_data["events"]`:
     - For `hit`/`ranged_hit`: show weapon indicator between attacker and target positions
     - For `defend`: show shield on the defender's cell
     - For `miss`/`ranged_miss`: show weapon indicator in the attack direction
   - Returns the decorated frame string

3. **Add `_build_combat_overlay()` method**:
   - Parse events to find attack/defend actions this round
   - Cross-reference with positions to get attacker/target coordinates
   - Return overlay dict: `{(x, y): indicator_str}` for cells that should show combat FX
   - Attack indicator placed between attacker and target (or in attack direction for miss)

4. **Keep `render_frame()` unchanged** — it remains the resolution frame

5. **Tests**: verify action frame shows indicators, resolution frame is unchanged

# Acceptance Criteria

- [ ] `render_action_frame()` produces a frame with combat indicators
- [ ] Attack indicators show directional weapon FX between attacker/target
- [ ] Defend indicators show 🛡️ on defending bot's cell
- [ ] `WEAPON_FX` dict allows easy addition of new weapon types
- [ ] Tests pass, ruff clean, < 400 lines
